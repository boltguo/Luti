Local capabilities

From code changes to a working preview.

Give your AI a task, and Luti runs the local steps on your Mac. Code, command output and screenshots can return to the conversation as tool results.

Read and change code

Search files and symbols, edit code, and review Git diffs. Structured file edits create a checkpoint before changing the file.

Run builds and tests

Run builds, tests and dev servers as background jobs. Read logs, respond to prompts, or stop a job from the conversation.

Check the actual page

Open your local preview, click through the page, and capture screenshots or PDFs. Inspect console errors and network requests.

Work with Mac apps

Inspect windows and interact with native apps and system dialogs, using the macOS permissions you grant.

Get started

Connect your AI. Try one task.

For ChatGPT, use OpenAI Secure MCP Tunnel. Your account and workspace need access to developer mode and tunnels. Other connection options are below.

  • Install Luti and select a project Download Luti, add your project folder in Projects, and start the runtime.
  • Connect an OpenAI Tunnel Create a tunnel in OpenAI Platform and associate your ChatGPT workspace. Enter its Tunnel ID and a runtime API key with tunnel Read + Use permissions in Luti → Connections → OpenAI, then enable the connection.
  • Add Luti in ChatGPT Enable developer mode in ChatGPT settings, then create an app from Apps. Choose Tunnel and select your Tunnel ID. Luti’s OpenAI connection does not use the public HTTPS OAuth flow.
  • Check the connection with a small task Select Luti in a new conversation and ask: “List the top-level files in my selected project.” Check that the result matches the folder on your Mac.

OpenAI Tunnel setup documentation ↗

Other remote clients · HTTPS + OAuth

Configure Cloudflare or ngrok in Luti’s Connections page. Add the full HTTPS MCP endpoint ending in /mcp to a client that supports remote MCP and OAuth. Complete OAuth and approve access on your Mac. Availability depends on the client and account.

Clients on this Mac · Local MCP

Start the runtime, then copy the Local MCP setup from Connections into your client’s MCP configuration. The setup includes the local endpoint and bearer credential; no remote tunnel is needed.

Browser automation currently requires Apple Silicon and an installed copy of Google Chrome.

Security

Choose what your AI can access.

Choose which projects to expose and configure tool permissions. Review calls and results in the local activity log.

  • One active project at a time Add projects on your Mac. Connected clients can switch between approved projects. Switching revokes the previous project’s workspace, jobs, browser and artifacts.
  • Authentication follows the connection Public HTTPS connections use OAuth and require approval on your Mac. OpenAI Tunnel uses workspace-authorized credentials; Local MCP uses a local bearer credential. Tool permissions apply separately.
  • Every call leaves a trace Review the caller, tool, time and result in the activity log. Caller identity comes from the authenticated connection.
  • Checkpoints for structured file changes The edit_files and path_action tools save a checkpoint before changing files. Restore locally with the runtime stopped. Shell commands and external app changes are not covered by these checkpoints.
  • Project context stays out of your repo Project memory, sessions and activity are stored under ~/.luti/, outside your repository. Connection credentials are stored in macOS Keychain.
  • Off means off Stopping the runtime closes its connections and stops the jobs and browser sessions it manages.

Where the boundary ends

  • Local execution is not an OS sandbox. Approved processes can run with your macOS user permissions.
  • Tool results reach your AI provider. This can include code, command output and screenshots. Luti does not operate a cloud service that receives your project data.
  • Only what passes through Luti is Luti’s responsibility. What a host runs elsewhere on its own is outside it.

How it works

The model thinks above. Luti works below.

The host owns understanding, planning and orchestration. Luti owns the project boundary, the persistent context, the local capabilities, the approvals and the record. Between them, only MCP.

Persistent context belongs to Luti.
Context intelligence belongs to the model.

Project capability belongs to Luti.
Reasoning and orchestration stay with the host.
