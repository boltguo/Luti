## 问题、原因与处理

| 问题 | 原因 / 判断 | 已做修改 | 验证与限制 |
| --- | --- | --- | --- |
| AX -25201 | 空 AXChildren 数组仍请求索引 0；并非所有 -25201 都等于权限未授予 | 先读取数量，限制预算；仅处理数组变空的竞态；错误标明操作、参数、权限与未知结果 | 单元测试及前台真实 MCP 已验证这一缺陷；其他应用的 AX 兼容性不等于全部通过 |
| window_not_frontmost | 全局 HID 输入依赖前台；用户切换窗口后安全保护阻止发送 | 正常激活后等待实际前台状态；后台实验改成按 PID/窗口派发 | 前台保护和激活已验证；真正共存需要更换输入架构 |
| Chrome 窗口遗漏 | helper 启动的 Chrome 没有 LaunchServices 启动日期，旧发现器将其过滤 | 内核进程启动时间作为身份补充，防止 PID 复用 | 独立 Chrome 在真实 MCP 中发现成功；针对性测试通过 |
| 多窗口后台键盘 | AXFocused 单独设置不足以确认目标窗口 | AXMain/元素焦点，精确 AX 窗口映射、焦点复查 | 两窗口验证：目标收到输入，另一窗口输入被拒绝 |
| 后台替换文本 | Chrome 收到 Command+A 但未执行菜单选择，继续输入可能追加 | AX 选区全选并回读确认；不支持则在发送前拒绝，禁止自动重放 | 原生驱动中文字/emoji 多批次替换通过；最终 MCP fallback 尚未验收 |
| 后台鼠标与可视化 | 全局鼠标会和用户竞争 | 私有事件源、窗口/PID 定向事件；不激活且穿透的独立指针 | 原生和 Chrome 点击、双击、右键、滚动、拖拽有实际效果；物理指针未移动 |
| App 管理通知 | 这项权限针对修改其他 App；日志显示 ad-hoc 测试进程与正式签名身份不同，Chrome 子进程触发权限检查 | 统一测试签名，说明它不是基本桌面控制必需权限 | 尚未定位被拒绝的具体文件操作；不能把该通知当作 AX 问题的根因 |

## 证据边界

- 早期前台修复：237 个自动化测试通过；70 次真实 MCP 调用记录包含预期保护错误和一次未定位的 MCP -32603，随后重读恢复。
- 后台实验：241 个测试通过；最后进程身份比较调整后另有 4 个针对性测试通过。
- 真实 MCP：原生后台点击；两窗口焦点保护；Chrome 点击、双击、右键、滚动与拖拽；普通字符输入。
- 使用生产 Swift 源码的签名驱动：多批次中文/emoji 替换、前台/系统指针保持、软件指针出现及自动隐藏。驱动结果不能替代最终 MCP 集成验收。
- Chrome 后台 Command+A 未执行全选。最终键盘 fallback、语义 Command+A、重启后的旧 observation 保护仍待验收。
- 输入定向使用动态 macOS 兼容接口，不能保证所有系统版本、应用或 Space。最小化/隐藏窗口可能不在当前观察列表；同时编辑同一字段仍共享状态。
- 删除前的 Computer Use Release 实验候选为 arm64/x86_64，签名检查通过，但未安装、未打包；已安装 App 是更早的实验构建，缺少最终选区确认修复。详见 JSON 的两个二进制哈希。
